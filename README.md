# 20 Newsgroups Text Classifier

This project is a notebook-based text-classification assignment using the **20 Newsgroups** dataset. It demonstrates an end-to-end natural language processing workflow in PyTorch:

1. Load and validate news articles stored in category directories.
2. Remove duplicate documents and inspect data quality.
3. Parse article headers and clean the message text.
4. Tokenize the text and build a vocabulary.
5. Convert tokens to integer IDs and create padded mini-batches.
6. Train a recurrent neural network (RNN) classifier.
7. Restore the best validation checkpoint and visualize test predictions with a confusion matrix.

The main implementation is in [`notebooks/nlp_classification_w_pytorch.ipynb`](notebooks/nlp_classification_w_pytorch.ipynb).

## Run the notebook

Open `nlp_classification_w_pytorch.ipynb` and execute the cells from top to bottom. Alternatively:

## Notebook workflow

### 1. Load and validate the data

`load_directory` walks through each category folder and creates a DataFrame with:

- `article_id`
- `category`
- `raw_text`

`validate_dataset` reports document counts, category counts, missing values, empty articles, duplicate article bodies, duplicate IDs, and whether the classes are balanced.

### 2. Preprocess the articles

The configurable `clean_text` pipeline:

- separates message headers from the body;
- retains the `Subject` header by default;
- optionally removes quoted lines and signatures;
- replaces URLs, email addresses, and numbers with placeholder tokens;
- lowercases and removes punctuation;
- normalizes whitespace;
- tokenizes with a simple word-oriented regular expression;
- removes scikit-learn's English stop-word list by default; and
- optionally applies Porter stemming.

The cleaned token lists are stored in `clean_tokens` and the space-separated cleaned text is stored in `clean_text`.

### 3. Build the vocabulary and encode documents

The vocabulary starts with two reserved tokens:

```text
<pad> -> 0
<unk> -> 1
```

The bundled run produces a vocabulary of approximately 31,500 tokens. Each document is converted to a list of token IDs. `collate_batch` pads documents within each batch so that they can be passed to the model as a tensor.

### 4. Split the data

The notebook encodes labels with `LabelEncoder` and uses a deterministic generator seed of `42` to create:

- 70% training data
- 15% validation data
- 15% test data

The DataLoaders use a batch size of 8.

### 5. Train the RNN classifier

`TextClassifier` consists of:

- an embedding layer with dimension 100;
- a one-layer vanilla RNN with hidden size 128; and
- a linear layer producing 20 class logits.

Training uses cross-entropy loss and Adam with a learning rate of `1e-3`. The training cell requests up to 100 epochs and saves the checkpoint whenever validation loss improves. Early stopping terminates training after five consecutive validation epochs without improvement.

The checkpoint contains:

- `model_state_dict`
- `optimizer_state_dict`
- `validation_loss`

It is saved as `notebooks/model_for_nuclei.pt` when the notebook is run as described above. The filename is retained from the existing notebook implementation.

### 6. Evaluate the model

The final cells restore the saved checkpoint, generate predictions for the test loader, calculate a confusion matrix, and display it with the 20 category names. The current notebook focuses on visualization and does not print aggregate accuracy, precision, recall, or F1 scores.

## Reproducibility notes

- The train/validation/test split is seeded with `42`.
- PyTorch model initialization and DataLoader behavior are not fully seeded in the notebook, so exact training results can vary between runs and hardware backends.
- The notebook saves and loads the checkpoint using a relative path. Always start Jupyter in `notebooks/`, or update the paths to absolute/project-root-relative paths.
- The saved checkpoint is binary and platform/backend dependent; retraining may be required when changing PyTorch versions or accelerator types.
- The notebook's displayed example run selected the Apple `mps` accelerator when available.
